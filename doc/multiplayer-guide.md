# 联机说明

> 最后更新：2026-08-24

## 架构

页面和 WebSocket 共用一个服务端口：

```text
浏览器 A ─┐
          ├─ HTTP 页面 + /ws ─ combined-server.js
浏览器 B ─┘
```

客户端会根据当前页面协议自动连接：HTTPS 页面使用 `wss://<host>/ws`，HTTP 页面使用 `ws://<host>/ws`，无需单独配置 WebSocket 地址。

## 本地联机

```bash
npm ci
npm run dev
```

默认端口为 `8080`；也可以通过 `PORT` 修改。同一局域网的玩家访问运行机器的 IP 和端口即可。

## 房间流程

1. 玩家设置昵称并连接；
2. 创建房间，按需设置密码；
3. 另一名玩家加入并选择空闲角色；
4. 剧作家选择剧本并开始游戏；
5. 旁观者可以加入，但不能执行角色操作。

惨剧轮回的角色席位为剧作家和主人公。连接断开后，服务器为有角色的玩家保留席位 2 分钟；同昵称重新连接时可恢复。

## 同步模型

- 服务端管理房间、连接、角色占用和最近一次完整游戏状态；
- 客户端操作后发送状态或动作，服务端转发给同房间其他客户端；
- 房间仅在内存中存在，服务器重启或房间所有连接离开后会丢失；
- 当前没有账号认证，房间密码只用于轻量访问控制。

## 排障

### 页面可访问但联机失败

1. 确认反向代理支持 WebSocket Upgrade；
2. 浏览器开发者工具中检查 `/ws` 请求；
3. 检查容器日志是否出现“WebSocket 客户端连接”；
4. 确认页面没有 HTTPS 与 `ws://` 混用。

### 无法恢复席位

- 使用断线前相同的昵称；
- 在 2 分钟宽限期内重连；
- 确认房间仍有其他连接，否则空房可能被清理。

生产发布、健康检查和回退见 [deployment.md](deployment.md)。
